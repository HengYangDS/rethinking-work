## Context

See [proposal.md](proposal.md) and the spec delta. `VERSION` is the version's one source (as in the owner's other
repositories); git is the source of whether a build is that version's release and of its date.

## Goals / Non-Goals

**Goals:**

- One place derives the edition's identity from git; every compile, test and archive reads it from there.
- A draft is visibly a draft on its cover, in its metadata and in its reader notes.

**Non-Goals:**

- Versioning policy, tag creation (ETHOS `land --release` owns the signed tag) or the CI label.

## Decisions

- The justfile declares one variable, `edition_inputs`, computed from git: when HEAD is the commit that `v<VERSION>`
  names and no tracked file differs from HEAD, `edition=release` with the tag's date; otherwise `edition=draft` with
  the commit, its date and whether tracked files differ. Typst receives them as `sys.inputs`; a compile without inputs
  is a draft. Tests ask the justfile for the same value (`just --evaluate`), so the build and the tests share one
  source. Alternative rejected: reading git from Typst (it cannot run commands) or a generated file (a second copy).
- The draft's PDF metadata carries its commit's date, so a draft build stays reproducible; its cover shows the commit,
  not a date.
- The hosted publication job fetches the tag ref on a tag event; the verification job's checkout is generated by
  ETHOS and is left as it is (its artifacts are not delivered).

## Risks / Trade-offs

- A release must be built after the tag exists (as 0.2.6 was); a build before it is a draft by design.
- A tag moved to another commit would change the edition; ETHOS's signed release tags are not moved.
